# Gama3 Orderak UX and delivery release — v1.8.1

## Objective

Make the group-ordering product simple on first use while preserving its advanced capabilities. The default flow is: create a shared menu, invite people, collect choices, finalize one order, and show a clear receipt.

## Baseline

- Public content had strong technical SEO but a documentation-heavy message and too many equal-weight navigation choices.
- The small-screen shell exposed too many controls at once.
- The dashboard showed statistics before a clear next action.
- Recent successful CI runs took roughly 34–35 minutes because unchanged Firebase targets were rebuilt and redeployed.
- Generated AI routing still referenced removed legacy folders.

## Changes

### Marketing and SEO

- Added conversion-focused English homepage copy and a three-step workflow.
- Reduced desktop public navigation to four primary links and one secondary menu.
- Improved shared-link title, description, Open Graph, Twitter card, image dimensions, secure image URL, and image alt metadata.
- Preserved canonical URLs, locale alternatives, structured data, prerendering, and multilingual content.

### App workflow and visual design

- Added a three-step dashboard journey: create a bucket, manage members, and review orders.
- Strengthened the main create action and reduced the visual weight of statistics.
- Added modern cards, forms, dialogs, focus states, spacing, touch targets, and responsive polish.
- Reduced always-visible mobile topbar controls while retaining existing settings and navigation.
- Preserved pricing, roles, sharing, group orders, notifications, repeat orders, order status, and receipt calculations.

### CI and Firebase

The new change planner selects only required Firebase targets:

| Change | Functions | Firestore |
|---|---:|---:|
| Frontend, content, docs, tests | No | No |
| Firestore rules or indexes | No | Yes |
| Function source or root dependency lock | Yes | No |
| Firebase config, release tag, manual run, unreliable diff | Yes | Yes |

Function source is built once before the existing sequential deployment batches. The selected plan is printed in CI.

### AI execution framework

The executive-function specification extends the repository's existing canonical rules, skills, knowledge, memory, and generated `.ai` layer. Added controls cover objective and Definition of Done locking, scope classification, bounded nesting and retries, evidence, context, durable memory, loop recovery, concise communication, verification, and termination. JSON/schema, TOON, SJON, state-machine, generator, and tooling-test layers are included.

## Regression matrix

- Public routes, locale redirects, titles, descriptions, canonicals, hreflang, social cards, structured data, and noindex boundaries.
- Account entry, registration, recovery, protected routes, session persistence, and logout confirmation.
- Bucket creation/editing, items, prices, fees, totals, filters, roles, and sharing.
- Friend requests, groups, multi-person sharing, notifications, and read state.
- Multi-participant order creation, contribution updates, totals, finalization, placement, completion, cancellation, repeat order, and receipt snapshots.
- Offline/reconnect, duplicate request, concurrent update, stale revision, empty selection, and permission cases.
- Desktop, mobile, tablet, RTL/LTR, keyboard, focus, touch target, dialog, safe-area, long-text, and overflow coverage.

## Required gates

Knowledge build/validation, agent docs, translations, formatting, lint, both TypeScript checks, unit/component/tooling tests, coverage, Firestore emulator tests, Cloud Function validation, dependency checks, public-content validation, web build, E2E/browser matrix, release checks, preview verification, and deployment health.

## Definition of Done

- The first action is obvious to a new user.
- The homepage explains the complete workflow quickly.
- Existing advanced features remain available and regression-tested.
- Link previews contain accurate metadata.
- Frontend/content-only pushes skip Firebase.
- Canonical and generated AI knowledge is current.
- Mandatory gates are green for the final branch head.
- No known blocking regression remains.
