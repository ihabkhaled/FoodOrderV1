# FoodOrderV1 v1.8.1

Upgrade the application, test, Firebase tooling, and GitHub Actions dependency stack.

## Highlights

- **Agent task routing was pointing at a layout that no longer exists.** The
  context command's path table still listed `src/pages`, `src/components`,
  `src/state`, `src/services`, and `src/lib` — directories the v1.6.0 module
  migration deleted. Seven of its twelve paths matched nothing, so most tasks
  scored zero and fell back to a generic `src/app` listing. Domains are now
  derived from `src/modules/*` plus checked cross-cutting areas, so a new module
  is routable the moment it exists and a deleted one cannot linger. A tooling
  test and `npm run ai:doctor` (wired into the CI Knowledge job) fail if a
  domain stops resolving.
- **The context command now compiles an answer instead of listing files to
  read.** `npm run ai:context -- --task="..."` writes `.ai/context/current.md`
  with the applicable rule obligations, the owning module's exported symbols,
  the covering tests, and a validation lane scaled to risk. Measured across
  eight representative tasks: 245–398 tokens per bundle against 4,041–14,154
  tokens to read the same sources, a 93–97% reduction, at ~190 ms cold and
  cached against the tree state. The riskiest domain sets the lane, so a
  Firestore-rules change stays critical even when a feature module scores
  higher.
- Added `test:ai`, `lint:ai`, `typecheck:ai`, and `build:ai`: one line on
  success, only the failing lines on failure, full log kept on disk. Added
  `.aiignore` recording the paths agents should never search.
- Upgraded Firebase to 12.17.0 and Firebase Tools to 15.25.0.
- Upgraded Playwright to 1.62.1, jsdom to 30.0.1, and Node.js types to 26.1.2.
- Upgraded transitive fast-uri to 3.1.5, ip-address to 10.4.0, and Undici to 6.28.0 or newer.
- Upgraded setup-node to v7, setup-java to v5.6.0, download-artifact to v8, and setup-android to v4.
