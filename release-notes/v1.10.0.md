# FoodOrderV1 v1.10.0

Shareable invite links, a complete mobile navigation bar, a public site that
finally explains itself, and a UI polish pass.

## Highlights

- **Shareable invite links for menus, friendships, and groups.** One link
  pasted into a group chat now does what four separate invitations used to.
  A bucket link lasts seven days, a friendship or group link twenty-four
  hours, and every link is multi-use, revocable, and idempotent - a shared
  link is opened more than once, and the second tap reports the access
  someone already has instead of an error. Sharing a friend link is the
  creator's consent, so only the person opening it has to agree.
- **The links are safe by construction.** The token is the whole secret and
  the document id, so a leaked link exposes nothing until redeemed and no
  resource id can be enumerated from it. Security Rules deny clients every
  write and allow a read only to the creator; redemption runs in callables
  that verify ownership and expiry. Rules tests cover both boundaries.
- **Signing in no longer loses where you were going.** The protected-route
  guard carries the attempted path through login and signup, and an
  already-authenticated visitor who lands on a sign-in page is sent to their
  pending destination rather than the dashboard.
- **The mobile bottom bar carries the marketing destinations.** It had only
  the five application pages, so a phone had no route back to Home, About, or
  Contact. Both navigation bars now build their links from one helper so they
  cannot drift apart, and the row scrolls horizontally rather than shrinking
  targets below the 44px minimum.
- **The public site explains itself.** Five step-by-step guides in all
  thirteen languages - creating a menu, sharing one, running a round,
  inviting friends, and working with groups - take English body content from
  about 1,521 words across 10 pages to 5,350 across 15, and the site from 130
  localized documents to 195. FAQ structured data is now emitted for any page
  with question-and-answer pairs, not only the FAQ page.
- **Sign in and sign up reachable from the public site**, with a globe on the
  language menu, a borderless theme toggle, and "Open App" in place of "Open
  the app".
- **UI polish.** The boot screen is a plain rotating loader; skeletons are
  reserved for lists and cards, where the shape of what is coming is known.
  Notification rows have contrast and room to wrap. The public footer is an
  inset card rather than a full-bleed band. The buckets filter row has
  spacing.

## Fixed

- A shareable URL built from the bare origin landed outside the router, which
  mounts under a `/{locale}` basename. Found by opening a generated link in a
  browser; no unit test would have caught it, so it is now written down as a
  rule and covered by a test.
- The private-path sitemap guard matched any prefix and flagged the
  invite-friends guide as the private `/invite` route. It now matches a whole
  path segment - stricter, not looser.
- The public catalogue required exactly ten pages, which would have blocked
  every future guide. It is now a floor.
